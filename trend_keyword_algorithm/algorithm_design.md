# SNS 트렌드 연관키워드 전체 MVP 설계

## 알고리즘 목표

입력된 검증 통과 트렌드와 사람이 수집한 SNS·뉴스·YouTube 문서에서 연관 후보 키워드를 수집하고, 정규화·역할 초안·근거를 만든 뒤 기존 `scorer.py`가 핵심·연관·소비 신호·제외를 판정하는 구조다.

## 전체 흐름

1. 트렌드 마스터에서 상태가 `검증 통과`인 트렌드를 선택한다.
2. 대표 트렌드명과 등록 별칭으로 검색 대상 표현을 만든다.
3. `raw_documents.csv`에서 대상 표현이 있는 문서만 고른다.
4. URL·텍스트가 같은 문서를 제거하고 텍스트를 정제한다.
5. 해시태그, 한글/영문 표현, 다단어 표현, 트렌드명과 결합한 행동 표현을 추출한다.
6. 후보의 반복 문서 수와 근거 URL을 집계한다.
7. 띄어쓰기·해시태그·줄임말 표기를 정규화해 통합한다.
8. 역할 초안을 추정한다.
9. `candidate_pool.csv`와 `candidate_review_template.xlsx`를 만든다.
10. 사람이 근거와 M:S 점수를 검토·입력한다.
11. 기존 `scorer.py`로 총점·등급·최종 판정을 계산한다.

## 후보 역할 초안 규칙

- 대표명·별칭: 트렌드명, 공백 제거 표기, 해시태그 표기, 등록 별칭과 같은 표현
- 소비 신호: 레시피, 만들기, 챌린지, 안무, 품절, 구매처, 오픈런, 맛집, 후기, 먹방 등 행동·구매 표현
- 확산 맥락: 브랜드, 밈, 아티스트, 프랜차이즈 및 유행 배경 표현
- 구성요소/제품·형태: 사람이 검토해 확정할 재료·제품명·형태명
- 불명확한 일반 명사와 고유명사는 `확인중`으로 둔다.

역할 초안은 최종 역할이 아니다. 자동 추정 결과는 검토 후 `candidate_review_template.xlsx`의 역할 열에서 확정한다.

## 중복과 근거 규칙

- `#탕후루`와 `탕후루`처럼 해시태그 차이만 있는 표기는 같은 정규화 키워드로 합친다.
- 영문은 대소문자를 통일하고, 공백 유무와 등록 별칭은 같은 후보로 통합한다.
- 같은 URL과 같은 정제 텍스트의 문서는 한 건만 사용한다.
- 등록 별칭은 문서 한 건에서도 후보로 남길 수 있다. 그 외 후보는 서로 다른 문서 두 건 이상에서 확인된 경우에만 남긴다.
- 후보별로 공동언급 문서 수, 플랫폼 수, 최초 발견일, 피크월, 피크월 시차, 최대 3개 URL, 짧은 근거 메모를 기록한다.

## 현재 MVP의 한계와 확장점

- 문서 수집은 별도 API 또는 사람이 만든 CSV가 필요하며, 이 코드가 외부 서비스에 접속하지는 않는다.
- 데이터랩은 새 후보를 찾아내는 도구가 아니라, 생성된 후보의 시점 동조성을 검토하는 근거다.
- M:S 점수 전부를 자동 산출하지는 않는다. 이번 MVP의 자동화 범위는 후보 수집·정규화·근거 연결까지다.
- 나중에 SomeTrend, YouTube, X 등의 API가 같은 `raw_documents.csv` 형식으로 데이터를 공급하면 후보 생성기를 그대로 재사용할 수 있다.

## 산출물

- `candidate_pool.csv`: 후보 검토 목록
- `candidate_evidence.csv`: 후보와 원문 근거 연결 목록
- `candidate_review_template.xlsx`: 사람이 M:S 점수를 입력하는 검토 템플릿

검토 템플릿의 M:S가 비어 있으면 `pipeline.py`는 `후보 수집 완료, 점수 검토가 필요합니다.`라고 안내하고 `scorer.py`를 실행하지 않는다.
