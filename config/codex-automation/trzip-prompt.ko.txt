매시 정각(KST)에 TRZIP 실데이터 수집과 로컬 분석을 실행한다. GitHub Actions, Windows 작업 스케줄러, X 전용 확장 프로그램은 사용하지 않는다.

chrome:control-chrome으로 찬희님이 로그인한 현재 Chrome의 https://x.com/explore/tabs/trending 를 연다. 로그인 상태와 대한민국 실시간 트렌드 페이지임을 확인하고, 프로모션을 제외한 data-testid=trend 순위 1~30을 정확히 수집한다. 결과는 schema_version=1, source=x, collector=codex_chrome_current_session, 실제 UTC observed_at, 정각 UTC scheduled_for, trigger=codex_hourly_direct, url, region=KR, region_verified=true, row_count=30, trends=[rank,topic] 형식으로 {{X_INBOX}}에 원자 저장한다. 누락·로그인 실패·지역 검증 실패 시 이전 시간 X 자료를 재사용하거나 합성하지 않는다.

{{PROJECT_ROOT}}\scripts\collect-hourly.ps1을 ProjectRoot={{PROJECT_ROOT}}로 실행한다. 같은 정각 Google Trending Now 대한민국 전체를 수집하고 SQLite 원장, 정규화, 사건 병합, 최근 24시간 분석, 맥락·키워드·기업 보강 상태를 갱신한다. 순위와 선발은 X와 Google 실제 수집값만 Python이 확정한다. NAVER 뉴스·공식 발표·공식 기업 페이지는 왜 지금 떴는지와 기업 연결 근거에만 사용하며 점수·순위·제품 적합도를 바꾸지 않는다. YouTube·Instagram·NAVER 블로그·카페·검색트렌드는 활성 순위 입력이나 자동 근거 수집에 사용하지 않는다.

00·04·08·12·16·20시와 일일 발행 시각에는 4시간 보강 체크포인트를 실행한다. 체크포인트는 실제 실행 구성요소를 attempted·completed·disabled_missing_config·deferred로 구분해 기록하고, 선택 기능 미설정을 완료로 가장하지 않는다. 04시 체크포인트의 06시 발행용 리뷰는 04:45 KST까지 종료하고, 그 뒤 도착한 검토 결과와 미완성 후보는 순위·점수를 바꾸지 않은 채 queue에 유지해 다음 체크포인트로 넘겨 수집·발행을 지연시키지 않는다. 안전 필터·8개 공개 카테고리·맥락·6글자 이하 키워드 정확히 5개·검증된 현재 상장기업 정확히 10개·기업 역할 3~4개·서로 다른 연결 키워드 최소 2개·기업 10곳 각각의 키워드 연결과 URL 근거를 갖춘 카드만 공개한다. 정치·선거·범죄·사망·사생활·혐오·직접 피해 중심 재난은 issue로 제외하고, 인물명 단독·동음이의어·광범위 일반명사·근거 부족은 review에 둔다.

hourly-source-proof-v3를 적용한다. X는 실제 수집기에서 정확히 30개의 고유 연속 순위, Google은 실제 수집기에서 최소 100개이며 declared_total과 일치하는 해당 시각의 전체 연속 순위여야 하고 둘 다 collection audit observed여야 한다. X에는 같은 현재 로그인 Chrome·대한민국 지역·정각 후 15분 이내 수집 증거가 있어야 한다. 최근 24시간의 다른 결측 시각은 감사에 남기고 허용하되 이전값 재사용·보간·가짜 채움은 금지한다.

frontend-result-quality-v9를 적용한다. 현재 프런트 기본 목록은 presentation_feed v4이며 완성 카드 0~10개만 제공하고 고정 Top10·참조 카드·이전 공개본·목업으로 패딩하지 않는다. 공개 기업은 공식 현재 상장 증명, 검증된 실제 이미지 로고, 서로 다른 실제 거래일 30개, 실제 원화 시가총액, PBR·ROE와 필드별 출처를 갖춰야 한다. PER은 최신 실제값일 때만 표시하고 적자·결측·오래된 값은 N/A로 둔다. 관심 흐름은 실제 관측 span·coverage가 충분한 기간만 측정값으로 표시하고 부족한 1개월·3개월을 0.0%나 합성 곡선으로 채우지 않는다. 시장·관심 보강은 display-only이며 canonical X·Google 순위에 영향을 주지 않는다.

매시간 X·Google 원천과 프런트 계약이 모두 통과하면 원격 게시와 분리된 immutable hourly_validation_receipt를 로컬 SQLite에 기록한다. 영수증은 해당 시각의 원천 스냅샷, publication_id, 프런트 manifest SHA-256을 함께 고정한다. 중복 실행은 동일 영수증이면 무변경 성공으로 처리하고, 같은 시각의 다른 내용은 충돌로 실패시킨다. 최근 8회 연속 정각 성공은 이 로컬 영수증으로만 계산하며 누락 정각과 mutex 충돌은 성공으로 세지 않는다. 이 연속 횟수는 운영 모니터링 지표이며 최근 24시간 결측 허용 정책과 별도로 보고한다.
