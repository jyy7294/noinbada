매시 정각(KST)에 TRZIP 실데이터 수집과 로컬 분석을 실행한다. GitHub Actions, Windows 작업 스케줄러, X 전용 확장 프로그램은 사용하지 않는다.

chrome:control-chrome으로 찬희님이 로그인한 현재 Chrome의 https://x.com/explore/tabs/trending 를 연다. 로그인 상태와 대한민국 실시간 트렌드 페이지임을 확인하고, 프로모션을 제외한 data-testid=trend 순위 1~30을 정확히 수집한다. 결과는 schema_version=1, source=x, collector=codex_chrome_current_session, 실제 UTC observed_at, 정각 UTC scheduled_for, trigger=codex_hourly_direct, url, region=KR, region_verified=true, row_count=30, trends=[rank,topic] 형식으로 {{X_INBOX}}에 원자 저장한다. 누락, 로그인 실패, 지역 검증 실패 시 이전 시간 X 자료를 재사용하지 않는다.

{{PROJECT_ROOT}}\scripts\collect-hourly.ps1을 ProjectRoot={{PROJECT_ROOT}}로 실행한다. 같은 정각 Google Trending Now 대한민국 전체를 수집하고 SQLite 원장, 정규화, 사건 병합, 최근 24시간 분석, 맥락·키워드·기업 보강 상태를 갱신한다.

순위와 선발의 원천 입력은 X와 Google 실측만 사용한다. NAVER 뉴스는 왜 지금 떴는지 맥락 근거에만 사용하며 점수·순위·제품 적합도를 바꾸지 않는다. YouTube, Instagram, NAVER 블로그·검색트렌드는 활성 순위 입력으로 사용하지 않는다.

hourly-source-proof-v3를 적용한다. X는 실제 수집기에서 정확히 30개의 고유 연속 순위, Google은 실제 수집기에서 최소 100개이며 declared_total과 일치하는 해당 시각의 전체 연속 순위여야 하고 둘 다 collection audit observed여야 한다. X 30개에는 같은 현재 로그인 Chrome, 대한민국 지역, 정각 후 15분 이내 수집 증거가 있어야 한다.

frontend-result-quality-v9를 적용한다. 현재 프런트 기본 목록은 presentation_feed이며, 완성 카드마다 검증된 현재 상장기업 정확히 10개를 제공한다. 각 카드는 1주·1개월·3개월 관심 추이, 출처가 있는 서로 다른 6글자 이하 키워드 정확히 5개, 명확한 기업 역할 3~4개, 공식·거래소 상장 근거, 검증된 실제 이미지 로고, 실제 30거래일 시장 데이터, 원화 시가총액, PER·PBR·ROE와 필드별 출처, 종목코드·거래소·연결 이유·근거 URL·온톨로지 경로·관계 등급을 갖춰야 한다. 이 보강값은 display-only이며 canonical X·Google 순위에 영향을 주지 않는다. canonical home_feed는 완성 카드가 없으면 empty일 수 있고 숫자를 맞추기 위해 패딩하지 않는다.

매시간 X·Google 원천과 프런트 계약이 모두 통과하면 원격 게시와 분리된 immutable hourly_validation_receipt를 로컬 SQLite에 기록한다. 영수증은 해당 시각의 원천 스냅샷, publication_id, 프런트 manifest SHA-256을 함께 고정한다. 중복 실행은 동일 영수증이면 무변경 성공으로 처리하고, 같은 시각의 다른 내용은 충돌로 실패시킨다. 최근 8회 연속 정각 성공은 이 로컬 영수증으로만 계산하며, 누락된 정각과 mutex 충돌은 성공으로 세지 않는다. monitoring/result_quality.json은 최신 로컬 실행과 현재 연속 성공 횟수를 반영한다.

매시간에는 원천 수집·로컬 분석·검증만 수행하고 live-data 원격 게시나 main 커밋을 하지 않는다. 매일 06:00 KST에만 X와 Google이 모두 정상인 최근 24시간 결과를 불변 프런트 publication으로 만들고 live-data에 게시한다. 이때 manifest SHA-256, publication_id, Git 객체, 로컬·원격 SHA 일치를 검증하고, 원격 publication receipt는 hourly_validation_receipt와 별도로 기록한다.

실패하면 원인과 실제 X·Google 행 수, 로컬 저장 여부, 현재 연속 성공 횟수만 간결히 보고한다. 성공하면 X·Google 행 수, hourly receipt 저장 여부, 현재 연속 성공 횟수, 완성 카드 수를 보고한다. 사용자 코드나 main을 매시간 임의 커밋하지 않는다.
