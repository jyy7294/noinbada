# TRZIP 제품 방향 결정

## 단일 페르소나

트렌드에는 민감하지만 그 트렌드가 어떤 기업과 산업에 연결되는지 모르는 20대 투자 관심자를 핵심 사용자로 둔다. 두 번째 상반된 페르소나를 동시에 만족시키려 하지 않는다. 서비스는 별도 앱이 아니라 키움 S# 내부 탑재 기능이며, 계좌가 없는 사용자도 트렌드와 기업 정보까지 탐색하고 매매 단계에서 로그인·간편인증·계좌 요건을 적용하는 흐름을 제안한다. 실제 구현 가능 범위는 키움 정책 검증이 필요하다.

## 핵심 문제와 가치

사용자는 유행을 보지만 왜 유행하는지, 어떤 기업이 실제 사업관계를 갖는지, 이미 널리 반영된 현상인지 새로 상승하는 현상인지 판단하기 어렵다. TRZIP은 실시간 한국 트렌드와 공식 기업 데이터를 연결해 `현상 발견 → 맥락 이해 → 관련기업 검증 → 기존 종목 화면 이동`을 한 흐름으로 만든다.

정보 비중은 트렌드 발견·해석 70%, 기업·투자 해석 30%로 둔다. 기능 수를 늘리는 것이 아니라 핵심 흐름의 설명력을 높인다.

여기서 트렌드는 장기간 정착이 끝난 문화만 뜻하지 않는다. X·Google에서 반복 측정되는 현재의 관심 현상을 넓게 포함하고, 짧은 유행과 지속 추세의 차이는 이름으로 미리 단정하지 않고 관측 지속성·모멘텀·마지막 관측시각·생애주기로 설명한다.

## 주식도 트렌드가 된 시대라는 진입 논리

핵심 사용자는 주식 전문가가 아니라, 주변의 투자 참여와 일상적인 주식 대화 때문에 “나도 시작해야 하나”를 고민하지만 기업을 고를 기준은 없는 20대다. 발표에서는 주식 투자가 일부 전문가의 행위에서 대중적인 참여 문화로 확장됐다는 문제 상황을 먼저 제시하고, 사용자가 이미 이해하는 음식·콘텐츠·패션·게임·생활 트렌드를 기업 탐색의 출발점으로 삼는 흐름을 보여준다.

종목명 자체가 X·Google 실시간 트렌드에 나타나는 경우도 숨기지 않는다. 다만 다음 규칙을 적용한다.

- 종목명이나 기업명이 실제 관찰됐다는 이유만으로 관련 기업을 추가하지 않는다.
- 실적·제품·산업 수요처럼 사업 맥락이 확인되면 메인 트렌드 후보가 될 수 있다.
- 단순 주가 급등락, 풍문, 경영진·연예인 사생활과 같은 원인이면 실시간 이슈로 분리한다.
- 종목명 트렌드는 해당 상장사를 직접 식별하고 사업·공시·시장 반응을 설명하되, 원인이 확인되기 전에는 공급망 수혜주를 확정하지 않는다.
- 발표용 홈 화면에 주식 키워드를 인위적으로 삽입하지 않고 실제 X·Google 관찰 결과에 따라 노출한다.

## 화면과 데이터 원칙

1. 이미 알려진 트렌드와 새로 떠오르는 트렌드를 하나의 전체 순위에 함께 표시한다.
2. 각 항목에 `신규 포착(new)`, `급상승(rising)`, `지속(sustained)`, `재부상(rebounding)`, `둔화(cooling)`, `기간 종료(expired)` 상태와 순위 변동을 표시한다. 대중화 여부는 별도 해석 문구로만 설명하며 구현에 없는 상태값을 만들지 않는다.
3. 단순 인물명·행정·사건 검색은 삭제하지 않고 실시간 이슈 레인으로 분리한다.
4. 운영자가 후보를 제안할 수는 있지만 X·Google 관측과 맥락 검증을 통과하기 전에는 공개 순위로 승격하지 않는다.
5. 공개 기업의 기계 관계 등급 `relation_tier`는 `core`, `value_chain`, `adjacent`로 구분하고, 사용자에게는 `직접 관계`, `가치사슬`, `산업 관찰`로 설명한다. `direct`, `indirect`, `sector_watch`는 이 등급에서 파생되는 표시 강도이고 `excluded`는 공개 등급이 아니라 제외 상태다. 선행 수혜나 주가 상승을 단정하지 않는다.
6. 기업 상세에는 관계 이유, 전달 경로, OpenDART 기업·사업 정보, pykrx 국내 종목명·일별 OHLCV와 위험·한계를 함께 표시한다. pykrx는 실시간 체결가로 표현하지 않는다.

## 밈트폴리오 경계

밈트폴리오의 사용자 구성·좋아요·수익률은 현재 프로토타입 목업이며 실제 운용 성과나 트렌드 순위 근거로 사용하지 않는다. 향후 과거 시점 성과를 붙이더라도 관측 이후 기간·비교기준·수수료 포함 여부를 표시한 역사적 시뮬레이션으로 분리하고, 미래 수익이나 매수를 보장하는 표현을 쓰지 않는다.

## 발표와 검증 흐름

발표는 `문제 사례 → 단일 페르소나 → 핵심 기능 → 실제 시연 → 기술·데이터 → 검증 결과 → 확장성` 순서로 구성한다. 두바이 초콜릿·불닭처럼 이해하기 쉬운 사례로 필요성을 제시하되, 과거 주가 상승을 미래 수익의 증거로 사용하지 않는다.

## KPI

MAU는 한 달에 한 번 방문한 사용자도 포함하므로 지속 사용을 단독으로 설명하지 못한다. 다음 퍼널을 핵심 KPI로 사용한다.

| 단계 | 지표 | 목적 |
| --- | --- | --- |
| 발견 | 트렌드 카드 도달 사용자 | 기능 진입 규모 |
| 이해 | 트렌드 상세 열람률 | 맥락 설명의 유효성 |
| 연결 | 트렌드→기업 클릭률 | 핵심 가치 검증 |
| 행동 | 기업→키움 종목화면 이동률 | 투자 탐색 전환 |
| 유지 | 7일·30일 재방문율 | 단발성 사용 여부 |
| 신뢰 | 관련기업 근거 열람률·오류 신고율 | 설명 신뢰성 |

초기 검증에서는 MAU 증가를 단정하지 않는다. 프로토타입 사용자에게 사용 의향을 묻는 것과 실제 사용 로그를 구분하고, 가능하면 아카데미 사용자 대상 반복 사용 테스트로 재방문을 측정한다.
