# TRZIP 백엔드 제품 정책 V3

## 목적

TRZIP은 한국에서 지금 관측되는 관심 표현을 지우지 않고 축적한 뒤, 그중 소비·문화·콘텐츠·제품·생활·스포츠·기술·시장 행동에 가까운 항목을 약하게 선별하고 증거가 완결된 관련 상장기업을 연결합니다.

핵심 사용자는 트렌드에는 민감하지만 그 현상을 기업·산업과 연결할 기준이 부족한 20대 투자 관심자 한 명으로 고정합니다. 제품은 별도 앱보다 키움 S# 안의 탐색 기능을 제안하며, 계좌가 없는 사용자도 트렌드·기업 정보까지 보고 종목화면 또는 매매 단계에서 인증·계좌 조건을 적용하는 흐름을 목표로 합니다. 실제 비로그인 범위·딥링크·계좌 정책은 키움 확인 전에는 구현 완료로 간주하지 않습니다.

## 권위 원천

- 순위 입력: X 한국 실시간 트렌드 1~30위, Google Trending Now 대한민국 전체 페이지
- 보조 검증: NAVER 뉴스·블로그, YouTube Data API, Instagram(인증 시), 검수된 기사
- 기업·시장 참고: 증거 온톨로지, pykrx 일별 시장자료, 선택적 OpenDART

기사·기업 수·카테고리는 관측 순위를 바꾸지 않습니다. NAVER 뉴스는 맥락 근거로만 사용하며 홈 순위에도 참여하지 않습니다. Google RSS, Trends MCP, X API, GitHub Actions, 생성·백필 데이터는 운영 경로에 없습니다.

## 순위

```text
기간별 점수 = 현재 관심 강도 35
             + 실제 상승 속도 25
             + X·Google 교차 확산 20
             + 관측 지속성 10
             + 최신성 10
```

- 일간 24시간, 주간 168시간, 월간 720시간을 제공하며 일간을 기본 화면으로 사용합니다.
- 기간강도는 원천별 정규화 위치의 `70% 신선도 가중 평균 + 30% 기간 최고점`을 원천 간 평균합니다.
- 상승 속도는 직전 동일 길이 기간을 우선 비교하고, 그 원장이 없으면 현재 기간 전반부와 후반부를 비교합니다. 양쪽 정상 스냅샷이 각각 3회 미만이면 `unavailable`·0점입니다.
- 신선도 반감기는 선택 기간의 절반이며, 60일 원장은 생애주기 판별에만 사용합니다.
- 원천별 검색량·게시량은 합산하지 않습니다.
- 선택 기간 안에 한 번 이상 실제 관측된 모든 항목을 후보로 유지하고, 현재 정각 관측 여부는 `is_current`와 `period_observed`로 구분합니다.
- 전체 순위는 개수 제한이 없습니다.
- 선택 기간의 원천별 관측 커버리지가 80% 미만이면 해당 기간을 `provisional`로 표시합니다. MVP 공개 이력 기준은 깨끗한 24시간입니다. 48시간은 운영 안정도 목표, 96시간은 장기 관찰 지표이며 둘 다 MVP 공개를 차단하지 않습니다.
- 발표용 연속 검증은 최근 8회 정각의 X 30개·Google 전체 수집 및 프런트 계약 성공을 로컬 원장에서 확인하고, 하루 한 번 생성되는 공개본의 원격 영수증을 별도로 검증합니다.
- `main/issue/review` 분류는 표시 위치만 정하며 점수는 그대로입니다.
- 60일 이력은 신규·재부상·지속·하락 생애주기 판정에 사용하되 점수를 직접 더하지 않습니다.
- 비교 가능한 기간이 없으면 상승으로 간주하지 않고 중립 처리합니다.

## 대표어와 관련어

- 대표어는 실제 원천 표현 중 현재 관측 여부 → 반복 시간 → 출처 수 → 역순위 근거 → 최고 순위 순으로 결정합니다.
- 정규화된 사건명은 그룹 키일 뿐 화면 제목을 대체하지 않습니다.
- 관련어는 같은 사건으로 관측된 원문 또는 Google이 제공한 관련 검색어만 최대 5개입니다.
- 근거가 없으면 0개가 정상이며 설명형 문장을 관련어로 만들지 않습니다.

## 약한 선별

- `main`: 제품·메뉴·콘텐츠·문화·밈·스포츠·소비·생활·기술·시장·주식
- `issue`: 정치·범죄·사건·재난·단순 기상특보·사생활 논란
- `review`: 실체나 맥락을 아직 식별하지 못한 표현

모든 관측어는 `all_observed_ranking`에 남습니다. 홈 `home_top10`은 점수를 재계산하지 않고 자동 제품 적합 규칙을 통과한 후보 중 앞 10개만 사용합니다. 기업 10개 준비 여부는 `company_ready_trends`로 분리하며 원천 점수에 영향을 주지 않습니다.

## 기사와 보조 플랫폼

기사는 이미 X·Google에서 관측된 표현의 소비·제품화 맥락을 설명할 수 있습니다. 기사만으로 관측 순위에 삽입할 수 없습니다. NAVER 뉴스는 항상 `ranking_effect=none`이고, YouTube·Instagram은 현재 활성 홈 경로에서 제외합니다.

## 관련기업

`관측 대표어 → 관측 관련어 → 개체·제품·인물·장소 → 산업 → 기업 → 상장종목` 경로의 모든 edge에 URL·근거 유형·기준일·검수상태가 있어야 합니다. 서로 다른 국내외 상장기업이 10개 이상이고 역할 카테고리가 2~4개면 `companies`가 준비 완료입니다. 미달이면 트렌드는 유지하고 `company_candidates`와 `enrichment_pending` 상태를 제공합니다. 무근거 단어 연상으로 숫자를 채우는 것은 금지합니다.

## 밈트폴리오

밈트폴리오는 현재 프런트 소유 목업입니다. 사용자 수·좋아요·수익률은 `live-data`의 실측 순위나 기업 Gold와 결합하지 않고 화면에 목업임을 고정 표시합니다. 향후 실제 관측 이후 성과를 계산하더라도 역사적 시뮬레이션으로 별도 계약하고 미래 수익 예측이나 매수 추천으로 표현하지 않습니다.

## 저장과 운영

- Raw/Bronze: 시간별 실제 원천 표현·순위·원본 payload
- Silver: 대표어·사건 그룹·관련어·출처 품질
- Gold: 전체 순위·메인 subset·완결 온톨로지 기업
- Audit: 수집 성공·실패, 검증 플랫폼, 기사 발견, 실행 안정성
- Output: `live-data` 브랜치의 정적 JSON

노트북이 종료·로그아웃된 시간은 결측으로 남기며 생성값으로 메우지 않습니다.
## YouTube 콘텐츠 발견 순위

- YouTube 검색 API는 기존 후보의 맥락 검증에 사용합니다.
- YouTube Data API 대한민국 `mostPopular` 차트는 영화·음악·게임을 발견하는 별도 콘텐츠 순위입니다.
- 동일 작품·곡·게임 영상은 사건 단위로 병합하되 X·Google 점수와 순위를 변경하지 않습니다.
- YouTube 차트에 없는 작품은 인기 트렌드로 임의 삽입하지 않습니다.
- 프런트 완성 목록은 관련어 정확히 5개, 검증기업 최소 10개, 역할 카테고리 2~4개를 요구합니다. 이 조건은 공개 준비 상태만 결정하며 원본 실측 순위와 점수에는 영향을 주지 않습니다.
