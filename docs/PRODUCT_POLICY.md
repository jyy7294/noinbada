# TRZIP 백엔드 제품 정책 V3

## 목적

TRZIP은 한국에서 지금 관측되는 관심 표현을 지우지 않고 축적한 뒤, 그중 소비·문화·콘텐츠·제품·생활·스포츠·기술·시장 행동에 가까운 항목을 약하게 선별하고 증거가 완결된 관련 상장기업을 연결합니다.

## 권위 원천

- 순위 입력: X 한국 실시간 트렌드 1~30위, Google Trending Now 대한민국 전체 페이지
- 보조 검증: NAVER 뉴스·블로그, YouTube Data API, Instagram(인증 시), 검수된 기사
- 기업·시장 참고: 증거 온톨로지, pykrx 일별 시장자료, 선택적 OpenDART

보조 검증·기사·기업 수·카테고리는 순위를 바꾸지 않습니다. Google RSS, Trends MCP, X API, GitHub Actions, 생성·백필 데이터는 운영 경로에 없습니다.

## 순위

```text
점수 = 현재 원천별 정규화 위치 40
     + 같은 원천의 정확한 직전 정각 대비 변화 20
     + 원천별 관측 지속성 × 96시간 성숙도 20
     + 24시간 반감기의 과거 관측 영향 15
     + 현재 X·Google 교차관측 5
```

- 원천별 검색량·게시량은 합산하지 않습니다.
- 현재 시간에 한 출처 이상에서 관측된 항목만 현재 순위에 남습니다.
- 전체 순위는 개수 제한이 없습니다.
- 96시간 전에는 순위를 `provisional`로 표시합니다.
- `main/issue/review` 분류는 표시 위치만 정하며 점수는 그대로입니다.
- 60일 이력은 신규·재부상·지속·하락 생애주기 판정에 사용하되 점수를 직접 더하지 않습니다.
- 직전 정각 스냅샷이 없으면 상승으로 간주하지 않고 중립 처리합니다.

## 대표어와 관련어

- 대표어는 실제 원천 표현 중 현재 관측 여부 → 반복 시간 → 출처 수 → 역순위 근거 → 최고 순위 순으로 결정합니다.
- 정규화된 사건명은 그룹 키일 뿐 화면 제목을 대체하지 않습니다.
- 관련어는 같은 사건으로 관측된 원문 또는 Google이 제공한 관련 검색어만 최대 5개입니다.
- 근거가 없으면 0개가 정상이며 설명형 문장을 관련어로 만들지 않습니다.

## 약한 선별

- `main`: 제품·메뉴·콘텐츠·문화·밈·스포츠·소비·생활·기술·시장·주식
- `issue`: 정치·범죄·사건·재난·단순 기상특보·사생활 논란
- `review`: 실체나 맥락을 아직 식별하지 못한 표현

모든 관측어는 `unified_ranking`에 남습니다. 홈 `trend_top10`은 점수를 재계산하지 않고 `main` 중 앞 10개만 사용합니다. 기업 5개 Gold 준비 여부는 `company_ready_trends`로 분리하며 Top10 선정에 영향을 주지 않습니다.

## 기사와 보조 플랫폼

기사는 트렌드 후보를 발견하고 이미 X·Google에서 관측된 표현의 소비·제품화 맥락을 설명할 수 있습니다. 기사만으로 순위에 삽입할 수 없습니다. NAVER·YouTube·Instagram도 검증 원장에 별도 저장하며 모든 행의 `ranking_effect`는 `none`입니다.

## 관련기업

`관측 대표어 → 관측 관련어 → 개체·제품·인물·장소 → 산업 → 기업 → 상장종목` 경로의 모든 edge에 URL·근거 유형·기준일·검수상태가 있어야 합니다. 서로 다른 국내 상장기업이 5개 이상일 때만 `companies`로 공개합니다. 미달이면 후보는 감사용 `company_candidates`에 남고 공개 Gold는 `ontology_incomplete`로 비웁니다. 기업을 채우기 위한 업종 일반화나 단어 연상은 금지합니다.

## 저장과 운영

- Raw/Bronze: 시간별 실제 원천 표현·순위·원본 payload
- Silver: 대표어·사건 그룹·관련어·출처 품질
- Gold: 전체 순위·메인 subset·완결 온톨로지 기업
- Audit: 수집 성공·실패, 검증 플랫폼, 기사 발견, 실행 안정성
- Output: `live-data` 브랜치의 정적 JSON

노트북이 종료·로그아웃된 시간은 결측으로 남기며 생성값으로 메우지 않습니다.
