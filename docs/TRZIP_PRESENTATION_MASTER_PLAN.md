# TRZIP 발표 마스터 플랜

기준일: 2026-08-17

대상: KDA 2차 프로젝트 최종 발표

목적: 시연 전후의 발표 흐름을 하나로 정리하고, 시연 직후 기술 파트를 실제 구현과 과장 없는 운영 목표로 완성한다.

## 1. 결론

TRZIP 발표는 **SNS가 주가를 예측한다는 발표가 아니라, 흩어진 관심 신호를 근거 있는 기업 탐색으로 바꾸는 서비스 발표**여야 한다.

현재 Figma 정리본은 시각 품질과 사례의 흡입력은 좋지만, 사례가 문제 정의보다 길고 사용자 검증·경쟁 비교·키움 성과 지표가 빠져 있다. 추천 흐름은 다음과 같다.

```text
한 개의 강한 사례
  → 사용자가 겪는 탐색 문제
  → 사용자·시장 검증
  → TRZIP의 해결 방식과 안전 기준
  → 시연 영상
  → 기술적 신뢰 구조
  → 키움에 주는 가치와 검증 계획
  → 클로징
```

기술 파트는 기술 로고 모음이 아니라 네 질문에 답해야 한다.

1. 실제 관심 신호가 어떻게 화면 데이터가 되는가?
2. AI와 결정론적 코드 중 누가 무엇을 결정하는가?
3. 관련 기업을 어떤 근거로 연결하는가?
4. 현재 MVP와 운영 목표는 어디까지 다른가?

## 2. 1차 발표자료에서 가져올 것과 버릴 것

| 참고 발표 | 가져올 강점 | 피할 약점 | TRZIP 적용 |
|---|---|---|---|
| K7 · KARI-NA | 문제에서 제품 파이프라인으로 이어지는 서사, 개인정보·신뢰 경계 | 모델 설명 반복, 전체 분량 과다 | 기술을 로고가 아니라 책임 경계로 설명 |
| 디지털원정대 · Picka | 시연 직후 아키텍처와 데이터 파이프라인 배치 | 기술 표와 점수표가 여러 장 반복 | 시연 뒤 기술 네 장만 사용 |
| 우아한 남매들 · RE:FLO | 20장 안쪽의 압축된 구조, 일관된 비주얼 | 기술 스택이 구현 목록처럼 보일 위험 | 메인 덱 16~18장, 부록 분리 |
| 미래안정형 | 상세 모델·수식은 부록으로 돌린 구조 | 본문과 Q&A 합계 52장으로 과도함 | 공식·테이블·ERD는 Q&A 부록으로 이동 |
| KDA증권 | AI는 보조하고 사람이 결정한다는 설명 | 제품 효용 전 기술 로고가 먼저 등장 | 시연 이후에만 기술 설명 |

강한 발표는 제품 효용을 먼저 보여 준 뒤 기술로 신뢰를 증명했다. TRZIP도 **시연 영상이 발표의 중간 전환점**이어야 한다. 시연 전에는 사용자가 왜 필요한지 설득하고, 시연 후에는 어떻게 믿을 수 있는지 증명한다.

## 3. 현재 Figma 정리본 감사

현재 `발표` 페이지에는 초기 18장 초안과 새 16장 정리본이 함께 있다. 실제 발표 기준은 오른쪽의 새 16장 정리본으로 고정한다.

### 잘된 점

- `두쫀쿠`라는 한 사례로 시작해 처음 보는 사람도 빠르게 진입할 수 있다.
- 시연 영상이 9번에 있어 문제·해결 이후 바로 제품을 증명한다.
- 클로징이 “종목 추천이 아닌 근거 있는 탐색”으로 마무리돼 금융 서비스의 경계를 지킨다.
- 흰 배경, 보라색 강조, 큰 문장 중심의 시각 체계가 일관된다.

### 반드시 고칠 점

1. **사례가 다섯 장으로 너무 길다.** 2~5번을 세 장으로 압축한다.
2. **`SNS → 소비 → 주가`가 인과처럼 보인다.** ‘주가 상승 원인’이 아니라 ‘탐색할 신호와 동시 관찰 사례’로 표현한다.
3. **사용자 수요 근거가 없다.** 설문에서 확인된 탐색 불편, 정보 이동, 기업 연결 수요를 한 장으로 넣는다. 검증된 숫자만 사용한다.
4. **경쟁 비교가 없다.** 토스증권 실시간이슈와 Google/X 트렌드의 역할을 짧게 비교한다.
5. **트렌드 선정·안전 기준이 본문에서 보이지 않는다.** 실측 원천, 안전 필터, 사람 승인 원칙을 시연 전에 한 장으로 보여 준다.
6. **키움에 주는 사업 가치가 빠져 있다.** 관련 기업 상세 진입, 종목 화면 전환, 재방문이라는 측정 가능한 KPI가 필요하다.
7. **팀 소개와 Q&A를 본문 장수에 포함할 필요가 없다.** 메인 메시지를 위한 장으로 활용하고 팀·Q&A는 엔딩 또는 부록으로 둔다.

## 4. 추천 메인 덱: 16장

| 장 | 역할 | 화면의 핵심 문장 | 발표 목적 |
|---:|---|---|---|
| 1 | 표지 | 오늘의 트렌드, 내일의 인사이트 | 한 줄 정의 고정 |
| 2 | 훅 | 이거, 먹어봄? | 두쫀쿠로 관심 유도 |
| 3 | 확산과 행동 | SNS의 반복 노출이 검색·구매·품절로 이어졌다 | 온라인 관심이 행동으로 번지는 장면 |
| 4 | 탐색 신호 | SNS는 주가 예측기가 아니라 소비 변화의 초기 단서다 | 과도한 인과 주장 차단 |
| 5 | 사용자 문제 | 투자자는 SNS·검색·뉴스·기업 정보를 직접 오간다 | 탐색 비용 정의 |
| 6 | 검증 | 실제 사용자도 트렌드와 기업 정보를 따로 찾고 있었다 | 설문·멘토 피드백 |
| 7 | 기존 서비스와 차이 | 원천 트렌드와 시장 이슈 사이의 기업 근거 탐색을 연결한다 | 토스·Google·X와 포지셔닝 |
| 8 | 해결 | 발견 → 맥락 → 기업 근거 → 종목 탐색 | TRZIP 핵심 흐름 |
| 9 | 선정·안전 기준 | 실측 원천, 안전 필터, 사람 승인 | 시연 데이터에 대한 신뢰 확보 |
| 10 | 시연 영상 | 하나의 트렌드가 기업 탐색과 저장으로 이어지는 과정 | 제품 증명 |
| 11 | 기술 구조 | 실측 신호가 서비스가 되기까지 | 전체 파이프라인 |
| 12 | 판단 경계 | AI는 설명하고, Python은 순위를 결정한다 | 재현성과 금융 안전성 |
| 13 | 기업 연결 | 관련 기업은 연상이 아니라 근거 경로로 연결한다 | 온톨로지 차별점 |
| 14 | 검증과 확장 | 지금의 MVP와 운영 목표를 구분했다 | 현재/목표 투명성 |
| 15 | 키움 가치 | 발견을 종목 화면 진입과 재방문으로 연결한다 | 도입 이유와 KPI |
| 16 | 클로징 | 다음 유행이 오기 전, SNS 유행을 투자 아이디어로 | 메시지 회수 |

팀 소개와 Q&A 표지는 본문 발표 시간이 끝난 뒤의 엔딩 화면 또는 부록으로 둔다.

## 5. 기존 정리본의 재배치

### 유지

- 기존 1번 표지
- 기존 2번 `이거, 먹어봄?`
- 기존 6번 탐색 문제
- 기존 7번 TRZIP 등장
- 기존 8번 서비스 구조
- 기존 9번 시연 영상
- 새로 완성한 기술 10~13번
- 기존 14번 클로징

### 압축

- 기존 3번 SNS 확산과 4번 산업·주가 연결을 한 장으로 합친다.
- 기존 5번 불닭·포켓몬빵은 대표 숫자 두 개만 남긴다. 모든 날짜·수치는 부록 근거표로 이동한다.

### 추가

- 설문 기반 사용자 검증 1장
- 기존 서비스와의 차이 1장
- 트렌드 선정·안전 기준 1장
- 키움 가치와 KPI 1장

## 6. 시연 직후 기술 파트

Figma의 기존 빈 프레임 `10 · 기술 구조`, `11 · 데이터`, `12 · 연결 로직`, `13 · 검증`은 다음 내용으로 채웠다.

### 10. 실측 신호가 서비스가 되기까지

```text
X·Google 실측
  → SQLite 원장
  → Python Trend Engine
  → AI 보강 + 사람 검토
  → Versioned JSON + 모바일 화면
```

> 수집·판단·설명·공개의 책임을 분리했습니다. 실제 관측이 없으면 만들지 않고, 결측은 숨기지 않습니다.

### 11. AI는 설명하고, Python은 순위를 결정합니다

| Python 책임 | AI 책임 |
|---|---|
| 실제 표현 정규화 | 모호한 표현의 맥락 검토 |
| 같은 사건 병합 | 왜 지금 관심을 받는지 설명 초안 |
| 안전 필터 | 기업 역할과 근거 URL 정리 |
| 점수와 순위 확정 | 사람 검토 큐 우선순위 |

> AI는 순위·점수·투자 판단을 바꾸지 않습니다. 설명은 유연하게 만들되, 순위는 재현 가능하게 유지합니다.

### 12. 기업 연결은 근거 경로입니다

```text
트렌드 사건
  → 실측 관련어
  → 사업 역할
  → 현재 상장기업
  → 공개 근거 URL
```

검사 항목은 공개 시점의 상장 상태, 브랜드·IP·제조·공급·유통 등 직접 역할, 기업별 연결 이유를 추적할 공개 자료다.

### 13. 지금의 MVP와 운영 목표

| 현재 MVP | 운영 목표 |
|---|---|
| 로그인 Chrome 기반 X 수집 | X API 또는 승인된 공식 커넥터 |
| Google Trending Now KR | 관리형 수집 실행기 |
| Python·SQLite 원장 | FastAPI·PostgreSQL·원본 저장소 |
| 선택적 AI 검토 | OpenAI Responses API 도구 호출 |
| Versioned JSON·Vercel 모바일 웹 | 사람 승인 콘솔·키움 S# WebView |

> 현재 구현과 향후 연동을 구분해 말하겠습니다. 기술은 바뀌어도 실측 원본 보존, Python 순위 확정, AI 보조, 사람 승인, 감사 가능한 발행 원칙은 유지됩니다.

## 7. 기술 스택을 말하는 올바른 방식

`Python, SQLite, OpenAI, Vercel` 로고를 한 장에 나열하지 않는다. 책임과 함께 말한다.

| 기술 | 왜 필요한가 | 발표 표현 |
|---|---|---|
| Python | 같은 입력에서 같은 정규화·병합·순위를 재현 | 순위를 결정하는 엔진 |
| SQLite | 시간별 원본, 결측, 감사 이력을 보존 | 실제 관측의 원장 |
| HTML/JavaScript | 빠른 모바일 MVP와 상호작용 검증 | 시연 가능한 모바일 화면 |
| Vercel | 버전이 고정된 정적 결과 배포 | 검증 결과 전달 |
| OpenAI API 목표 | URL 근거 기반 맥락·기업 보강 자동화 | 순위를 바꾸지 않는 검토 보조 |
| FastAPI/PostgreSQL 목표 | 수집·승인·앱을 분리하고 운영 확장 | 운영형 API와 감사 저장소 |

TRZIP은 ‘AI 에이전트 앱’보다 **Human-in-the-loop Trend Intelligence Engine**으로 설명하는 것이 정확하다.

## 8. 발표 시간 배분

12분 발표와 4분 시연을 기준으로 한다.

| 구간 | 시간 | 기준 |
|---|---:|---|
| 사례와 문제 | 2분 20초 | 성공 사례보다 사용자의 탐색 문제에 더 오래 머무르지 않음 |
| 검증·차별점·해결 | 2분 10초 | 설문 숫자 2~3개, 비교 표 1개 |
| 시연 | 4분 | 트렌드 선택 → 관련 기업 → 기업 시트 → 저장 또는 종목 화면 |
| 기술 4장 | 2분 20초 | 장당 30~40초 |
| 키움 가치·클로징 | 1분 10초 | KPI 3개와 한 문장 회수 |

시연 영상이 5분이면 사례 설명을 한 장 더 줄이고 기술 파트를 2분 안으로 압축한다. 기술 장수를 줄이지 말고 각 장의 말만 줄인다.

## 9. 키움 가치와 KPI 슬라이드

> 트렌드를 보여주는 데서 끝나지 않고, 기업 탐색과 기존 종목 화면 진입을 늘립니다.

파일럿 KPI:

1. 트렌드 상세에서 관련 기업 보기 클릭률
2. 기업 바텀시트에서 키움 종목 화면 전환율
3. 7일 재방문율
4. 연결 근거 열람률
5. 사람 검토 시 기업 연결 수정률

MAU 증가를 곧바로 수치로 약속하지 않는다. 먼저 선행지표를 파일럿에서 측정하고, `대상 고객 수 × 서비스 진입률 × 재방문 증가`로 MAU 기여를 추정한다.

## 10. 경쟁 비교 한 장

| 서비스 | 출발점 | 잘하는 일 | TRZIP의 빈자리 |
|---|---|---|---|
| X | 실시간 대화 | 지금 언급되는 표현 발견 | 사건 맥락·기업 근거 부족 |
| Google Trends | 검색 관심 | 검색량 변화 확인 | 상장기업 탐색 연결 부족 |
| 토스증권 실시간이슈 | 시장·뉴스 이슈 | 시장에서 움직이는 이유 해석 | SNS 소비·문화 신호에서 시작하는 탐색은 제한적 |
| TRZIP | SNS·검색 관심 신호 | 사건 정리 → 기업 역할·근거 → 종목 탐색 | 정확도·전환율을 파일럿에서 검증해야 함 |

`경쟁 서비스보다 무조건 빠르다`고 말하지 않는다. **출발점과 사용자 흐름이 다르다**고 설명한다.

## 11. Q&A 답변 원칙

### SNS가 주가를 올린다는 뜻인가요?

아니다. SNS는 소비 변화의 초기 단서다. 실제 기업 검토는 판매·기사·공시·실적을 함께 본다. 사례는 인과 증명이 아니라 탐색 가능성을 보여 주는 관찰 사례다.

### 광고·봇·조작된 유행은 어떻게 거르나요?

단일 언급량만 보지 않는다. X와 Google의 실제 관측, 반복성, 출처 상태, 안전 필터를 먼저 확인하고 공개 전 사람 검토를 거친다. 이상행동 탐지는 운영 고도화 과제다.

### 관련 기업을 억지로 붙인 것 아닌가요?

트렌드 → 실제 관련어 → 사업 역할 → 상장기업 → 근거 URL 경로가 성립해야 한다. 근거가 부족하면 기업을 공개하지 않는 것이 원칙이다.

### 지금 실제 실시간 서비스인가요?

실제 수집 파이프라인과 모바일 MVP는 구현돼 있다. 다만 시연 화면과 실제 발행 체인의 완전한 정합화, 공식 API, 승인 콘솔과 키움 앱 연동은 운영 단계 과제다. 현재 구현과 목표 구조를 구분해 보여 준다.

### 종목 추천과 무엇이 다른가요?

매수·매도·목표가를 제시하지 않는다. 기업이 어떤 사업 역할로 연결되는지 확인하고 기존 종목 분석 화면으로 넘어가는 탐색 서비스다.
