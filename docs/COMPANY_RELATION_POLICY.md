# 관련기업 관계 정책 V1

## 목적

트렌드와 기업의 단어 유사성이 아니라 공식 사업관계를 설명한다. 관련기업은 트렌드 점수와 별도 분석 계층이며 주가 상승·수혜를 의미하지 않는다.

## 관계 등급

- `direct`: 공식 제조사, 소유자, 제작사, 배급사, 서비스 제공사
- `indirect`: 공식 공급·유통·원재료·후원 관계가 확인된 경우
- `sector_watch`: 산업 노출 가능성은 있으나 해당 사건과 직접 계약·제품 관계는 미확인
- `excluded`: 테마주식 연상, 단어 유사성, 같은 업종이라는 이유뿐인 약한 연결

## 기업 역할 7개

- `브랜드·IP`: 브랜드, 콘텐츠, 아티스트, 서비스의 권리·운영 주체
- `제조`: 완제품 생산 및 공식 제작사
- `원재료·부품`: 식재료, 소재, 부품, OEM·ODM 등 공급 단계
- `유통·리테일`: 도매, 소매, 편의점, 백화점, 이커머스
- `플랫폼·채널`: OTT, 앱스토어, 포털, 결제·중개 채널
- `공간·운영`: 팝업, 공연장, 상권, 체험 공간 운영
- `인프라·서비스`: 물류, 광고, 클라우드, 기술 솔루션 등 지원 단계

## 사용자 노출 단계

1. `핵심 사업자`: 트렌드 대상의 브랜드·IP·제조·공식 서비스 주체
2. `가치사슬 기업`: 공식 공급·부품·원재료·유통·플랫폼 관계가 확인된 기업
3. `확장 관찰기업`: 동일 수요에 구조적으로 노출되지만 특정 계약은 미확인인 기업
4. `연결 제외`: 단어 유사성이나 테마주 연상에 불과한 기업

확장 관찰기업을 선행 수혜기업으로 표현하지 않는다. `왜 관찰하는지`, `무엇이 추가로 확인돼야 하는지`, `이미 시장 반응이 나타났는지`를 별도 필드로 제공한다.

## 현상 중심 확장 탐색

기업 탐색은 키워드의 가장 직접적인 제품에서 멈추지 않고, 사용자가 실제로 행동하고 돈을 쓰는 장면을 기준으로 확장한다.

예를 들어 `야구 관람 열기`는 야구용품 제조사만 찾지 않는다.

1. 구단·리그·경기 주최자
2. 중계·티켓 플랫폼
3. 유니폼·굿즈·패션 협업
4. 경기장·복합공간 운영
5. 경기장 안팎 식음료·편의점·외식 소비
6. 공식 스폰서·브랜드 콜라보
7. 이동·숙박 등 관람객 소비 인프라

각 후보는 `현재 직접 연결`, `현재 가치사슬 연결`, `확장 기회 관찰`, `연결 제외` 중 하나로 표시한다. `확장 기회 관찰`은 선행 수혜 기업이나 상승 예상 기업을 뜻하지 않으며 추가 확인 항목과 근거 상태를 함께 표시한다.

## 후보 생성 순서

`현상 정의 → 소비 행동 → 지출 접점 → 가치사슬 역할 → 상장기업 후보 → 공식 근거 검증 → 시장반응 참고`

한 역할에서 같은 기업을 무제한 제시하지 않고 역할별 최대 2개, 트렌드별 최대 8개를 기본값으로 한다. 직접 관계만으로 목록을 채우지 못하더라도 검증되지 않은 후보를 확정 관계로 승격하지 않는다.

## 최소 3개 사업 카테고리 규칙

모든 메인 트렌드는 최소 3개의 서로 다른 사업 연결 카테고리를 제공하고 각 카테고리에 기업을 1개 이상 배치한다. 카테고리는 고정된 동일 명칭 3개가 아니라 트렌드 유형에 따라 동적으로 선택한다.

- 음식: 원재료·식품소재 / 제조·브랜드·상품 / 유통·외식·판매채널
- 음악: IP·기획·제작 / 플랫폼·유통·미디어 / 공연·티켓·팬덤소비
- 게임: 게임·IP·운영 / 방송·커뮤니티·플랫폼 / 기기·통신·인프라
- 스포츠: 스포츠웨어·용품 / 미디어·중계·플랫폼 / 시설·현장·주변소비
- 영상: 콘텐츠·IP·제작 / 배급·플랫폼·채널 / 기기·패키지·소비

직접 관계가 없는 카테고리에는 업종·가치사슬 대표기업을 `산업 구조 후보`로 제시할 수 있다. 이 후보는 실제 계약이나 수혜기업으로 표시하지 않으며, 개별 관계를 확정하려면 근거 URL·관계 문장·기준 시점 검증을 통과해야 한다.

## 공식 검증 순서

1. 회사·브랜드·콘텐츠 공식 페이지
2. OpenDART 고유번호·종목코드·공시 원문
3. pykrx 국내 종목명·일별 OHLCV 참고자료
4. 회사 IR·제품·공급·유통·후원 자료
5. pykrx 일별 주가자료는 관계 판정과 트렌드 순위에는 사용하지 않음

인증이 없으면 `pending` 또는 `unavailable`로 남기며 확인된 관계로 승격하지 않는다.

## 구현된 검증 경로

- OpenDART `corpCode.xml`에서 회사명을 정확 일치시키고 `company.json` 기업개황을 조회한다.
- OpenDART 종목코드와 pykrx 종목명을 교차 확인하고 최근 일별 OHLCV를 참고자료로 표시한다.
- 외부 인증이 없는 상태에서 기존 레지스트리 후보를 공식 검증 완료로 표시하지 않는다.
