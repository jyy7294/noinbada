# TRZIP 멘토 피드백 실행 맵

기준일: 2026-08-15
목적: 멘토 피드백을 현재 구현·데이터 계약과 대조해, 지금 유지할 범위와 다음 검증 순서를 한 문서로 고정합니다.

## 한 줄 결론

TRZIP의 MVP는 **X·Google에서 관측한 생활·소비·문화 흐름을 안전하게 선별하고, 왜 관련 기업인지 설명해 종목 탐색으로 이어 주는 기능**입니다. 기능을 더 넓히기보다 `선정 기준 공개 → 기업 연결 설명 → 검수된 지난 사례 → 다음 행동 측정`의 신뢰 사슬을 먼저 완성합니다.

## 1. 현재 확정한 제품 경계

| 영역 | 현재 결정 | 구현·계약 근거 |
|---|---|---|
| 실시간 원천 | X 대한민국 실시간 트렌드와 Google Trending Now 대한민국만 점수·순위에 사용 | `README.md`, `docs/HOME_FEED_CONTRACT_V1.md` |
| 보조 근거 | NAVER 뉴스는 `why_now` 맥락만 보강하며 순위에는 영향 없음 | `ranking_effect=none` |
| 비활성 원천 | YouTube·Instagram·NAVER 블로그·검색트렌드는 현재 홈 선발에서 사용하지 않음 | `README.md`의 데이터 역할 표 |
| 홈 | 프런트는 최근 24시간 실측에서 완성 계약을 통과한 `presentation_feed.items` 0~10개만 사용하고, 원장 전체는 `all_observed_ranking`에 분리 보존 | `frontend/index.html`, `docs/FRONTEND_COMPLETION_CONTRACT.md` |
| 관련 기업 | 회사명 나열이 아니라 역할·연결 이유·종목코드·거래소·근거 경로를 제공 | `docs/COMPANY_RELATION_POLICY.md` |
| 밈트폴리오 | 현재는 브라우저 저장 기반 데모이며 실사용자 수·좋아요·성과 데이터로 간주하지 않음 | `docs/PRODUCT_POLICY.md`, `frontend/trendzip-data.js` |

과거 문서에 남은 YouTube·Instagram 확대, NAVER 블로그 활용, 생성·백필 데이터의 실시간 혼합, 풍부한 수익률 목업은 현재 MVP 결정이 아닙니다. 이 문서와 `README.md`의 현재 운영 경계를 우선합니다.

## 2. 멘토 피드백 중 지금 구현된 것

1. **선정 기준 고지**
   홈의 `선정 기준` 화면이 원천 관측, 사건 병합, 안전 필터, 공개 순서를 설명합니다. 정치·범죄·재난·사생활·혐오 및 맥락 불명 표현을 공개 대상에서 제외한다고 명시합니다 (`frontend/index.html`의 `openSelectionGuide`).

2. **기업 연결 이유 제공**
   실시간 카드의 기업 계약은 `connection_explanation`, `company_role_label`, `ontology_path`, 공개 근거 URL을 요구합니다. 지난 사례에서는 `connection_context`와 역할을 표시합니다. 화면의 목적은 추천이 아니라 관계 탐색입니다.

3. **검수된 지난 사례 아카이브**
   `지난 트렌드` 화면에서 검수된 50건을 날짜순으로 열람하고 카테고리로 거를 수 있습니다. 각 사례는 `why_now`, 최대 5개 키워드, 최대 3개 기업과 연결 맥락을 제공합니다 (`src/trzip/archive_feed.py`, `frontend/trend-archive.json`).

4. **밈트폴리오 최소 안전장치**
   이름·키워드에 정치, 범죄·참사·사생활, 혐오, 수익 보장·리딩 표현이 있으면 생성을 차단합니다 (`validatePortfolioContent`). 저장·삭제는 브라우저 로컬 데이터에만 적용됩니다.

5. **행동 측정 지점 마련**
   트렌드 노출·상세, 기업 클릭·근거 보기, 키움 종목 이동·관심기업, 아카이브 열기·필터·사례 열기, 밈트폴리오 생성·차단 이벤트를 `trzip:analytics`로 발생시킵니다. 다만 아직 수집 서버가 없어 실제 KPI 집계는 되지 않습니다.

## 3. 지난 트렌드 아카이브 계약

아카이브는 **과거 순위표가 아니라 검수된 리서치 사례집**입니다.

- 스키마: `trzip-archive-feed-v1`
- 데이터 모드: `reconstructed_reference`
- 표시 모드: `historical_research_archive`
- 실시간·순위 자격: `live_eligible=false`, `ranking_eligible=false`, `ranking_effect=none`
- 정렬: `peak_hint` 최신순, 동률이면 이름순
- 공개 조건: `review_status=ready`, 공개 HTTP(S) 근거, `why_now`, 안전 주제 통과
- 항목 필드: 날짜, 카테고리, 정의, 촉발 맥락, `why_now`, 키워드, 기업 연결 맥락, 사례 근거 URL

따라서 아카이브에는 숫자 순위, 당시 실시간 1위 같은 표현, 검증하지 않은 주가 성과를 넣지 않습니다. 실제 과거 X·Google 원장과 시장 반응 데이터가 확보될 때만 별도 계약으로 확장합니다.

## 4. 신뢰·안전 경계

- 정치·선거, 범죄, 사망·참사, 사생활 폭로, 혐오를 홈과 아카이브의 기본 공개 범위에서 제외합니다.
- 공공·소비자 안전 이슈는 피해 자극이 아니라 소비·산업 연결을 공개 근거로 설명할 때만 검토합니다.
- `수혜주`, `오를 기업`, `매수 추천`, 수익 보장처럼 방향을 단정하지 않습니다.
- 기업 수를 맞추기 위해 산업 대표기업을 채우지 않습니다. 실시간 완성 카드는 근거 있는 상장기업 10개와 역할군 2~4개 계약을 통과해야 합니다.
- 관계 등급과 검수상태는 백엔드 감사 필드로 유지하되, 고객 화면에서는 이해 가능한 역할과 연결 이유를 우선합니다.
- 인기 밈트폴리오 4건은 프런트 내부에서 `seed_portfolio`로 격리한 제품 데모입니다. 라이브 트렌드·기업·순위·시장자료를 만드는 입력으로 절대 재사용하지 않습니다. 서버 측 신고·검수·차단 체계가 생기기 전에는 공개 UGC 서비스로 발표하지 않습니다.

## 5. 이슈·뉴스 서비스와의 차별화 가설

TRZIP의 차별화는 경쟁 서비스보다 더 많은 뉴스를 보여주는 데 있지 않습니다.

```text
생활·소비·문화 트렌드 발견
→ 왜 지금 확산됐는지 확인
→ 사업 역할과 기업 연결 이유 이해
→ 키움 종목홈 또는 관심기업으로 이동
```

즉, 뉴스·시장 움직임에서 출발하는 일반적인 이슈 해석이 아니라 **사람들의 생활·문화 관심에서 기업 탐색을 시작하는 역방향 진입점**을 제안합니다. 이는 아직 비교우위가 입증된 사실이 아니라 사용자 검증이 필요한 제품 가설입니다. 아카이브는 이 가설을 설명하는 사례 자료이고, 실제 우위는 다음 KPI로 판단합니다.

## 6. 수요와 MAU를 검증할 KPI

목표 수치는 현재 근거가 없으므로 임의로 정하지 않습니다. 먼저 파일럿 기준선을 수집한 뒤 대조군 또는 같은 진입 위치의 전후 비교로 목표를 확정합니다.

| 질문 | KPI와 계산 | 현재 계측 상태 |
|---|---|---|
| 트렌드가 기업 탐색을 유도하는가 | `기업 카드 클릭 사용자 / 트렌드 상세 사용자` | 이벤트 있음, 수집 서버 없음 |
| 연결 근거가 실제로 읽히는가 | `기업 근거 보기 사용자 / 기업 카드 클릭 사용자` | 이벤트 있음, 수집 서버 없음 |
| 키움의 다음 행동으로 이어지는가 | `종목홈 이동 사용자 / 기업 카드 클릭 사용자`, `관심기업 등록 사용자 / 기업 카드 클릭 사용자` | 이벤트 있음, 실제 딥링크·계정 연동 미검증 |
| 지난 사례가 신뢰를 보강하는가 | `아카이브 열람 사용자 / 홈 사용자`, `사례 연결 맥락 열람 사용자 / 아카이브 사용자` | 이벤트 있음, 수집 서버 없음 |
| 밈트폴리오가 재방문 이유가 되는가 | 생성 전환율, 저장 후 7일·28일 재방문율 | 생성 이벤트만 있음, 사용자 식별 없음 |
| S# MAU에 기여하는가 | 노출군과 비노출군의 월간 활성·방문일수·재방문 차이 | S# 연동과 실험 설계가 없어 미측정 |

MAU 증대를 주장하려면 최소한 `진입 노출 → 트렌드 상세 → 기업 상세 → 종목홈/관심기업 → 재방문` 퍼널과 사용자 단위 월간 식별이 필요합니다. 현재 프런트의 `CustomEvent`만으로는 MAU 효과를 입증할 수 없습니다.

## 7. 현재 데모의 한계

- 지난 50건은 검수된 재구성 자료이지 당시 실시간 순위가 아닙니다.
- 아카이브 원천에는 기업 주가 반응 결과가 없어 과거 성과를 제시하지 않습니다.
- 밈트폴리오의 사용자·좋아요·구성 등락은 제품 흐름 데모이며 실제 커뮤니티·성과 데이터가 아닙니다.
- 키움 종목홈 이동, 관심기업 저장, 로그인·계좌 정책은 실제 S# 연동 검증이 남아 있습니다.
- 분석 이벤트는 브라우저에서 발생하지만 저장·집계·사용자 동의·실험 배정 계층이 없습니다.
- 실시간 운영 완료는 코드 테스트와 별개입니다. 최근 24시간의 실제 관측시간 수·결측시간·마지막 성공시각과 일일 publication 영수증을 함께 확인해야 합니다. 결측시간은 허용하되 재사용·보간·생성으로 메우지 않습니다.
- 기업 시장반응은 외부 요인이 많으므로 향후 표시하더라도 인과나 미래 수익의 증거로 표현할 수 없습니다.

## 8. 우선순위 백로그

### Must — 발표·MVP 전에 반드시

1. 공개 카드 0~10개 각각의 `why_now`, 키워드 정확히 5개, 기업 정확히 10개, 역할 2~4개, 기업별 연결 이유·근거 및 기업과 연결되는 서로 다른 키워드 2개 이상 계약을 E2E로 검증합니다.
2. 최근 24시간의 X·Google 실제 관측시간, 결측시간, 마지막 성공시각과 일일 불변 publication 영수증을 확인합니다. 수집 공백은 그대로 남기고 이전 시각 자료로 채우지 않습니다.
3. `trzip:analytics`를 익명 사용자·세션·유입경로와 함께 저장하는 최소 계측 계층을 만들고, `선정 기준 열기` 이벤트도 추가합니다.
4. 키움 종목홈 딥링크와 관심기업 저장의 실제 동작·실패 경로를 검증합니다. 실제 S# 연동 전에는 외부 이동을 성공 처리하지 않고 안전한 미연결 상태로 종료합니다.
5. 공개 밈트폴리오는 로컬 데모로 유지하고, 실제 공유를 열기 전 서버 측 금칙어·신고·삭제·운영자 검수 정책을 설계합니다.

### Next — 파일럿에서 검증

1. 동일한 S# 진입 위치에서 노출군·비노출군 또는 단계적 출시로 퍼널과 재방문 차이를 측정합니다.
2. 아카이브 열람 전후 기업 근거 보기·종목홈 이동 차이를 측정해 신뢰 보강 효과를 확인합니다.
3. 실제 과거 원장과 시장자료가 쌓인 사례만 `T+1·T+3·T+5 거래일 시장·업종 대비 반응`으로 별도 제공하되 인과 해석을 금지합니다.
4. 사용자 인터뷰·설문으로 트렌드 선정 기준, 기업 연결 이유, 위험 고지의 이해도를 확인합니다.

### Later — 수요가 확인된 뒤

1. 기업 재무·밸류에이션 심층 분석은 키움 기존 종목홈과 중복을 검토한 뒤 필요한 연결만 추가합니다.
2. YouTube·Instagram 등 원천 확대는 공식 접근권한, 비용, 중복 제거 성능, 실제 추가 가치가 확인될 때 재검토합니다.
3. 검색·타임라인·과거 사례 성과 비교 등 아카이브 고도화는 아카이브 사용률이 확인된 뒤 진행합니다.
4. 공개 밈트폴리오 피드·랭킹은 안전 운영과 오인 방지 실험을 통과한 뒤 검토합니다.

## 9. 발표에서 사용할 정직한 표현

> TRZIP은 X와 Google의 관심 흐름에서 생활·소비·문화 트렌드를 찾고, 공개 근거로 왜 지금 떴는지와 기업의 사업 연결 이유를 보여줍니다. 관련 기업은 추천 목록이 아니라 추가 탐색의 출발점입니다. 지난 트렌드는 검수된 사례 아카이브이며 실시간 과거 순위나 수익 성과로 사용하지 않습니다.
