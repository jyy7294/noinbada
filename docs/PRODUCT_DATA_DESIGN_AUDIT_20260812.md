## 결론

현재 제품은 과거 모션 프로토타입보다 화면 수와 실제 데이터 연결 범위는 늘었지만, **실측 이력과 사건 정규화 정확도가 아직 제품 메시지를 뒷받침할 수준은 아닙니다.** 따라서 과거 프로토타입의 모션을 복원하는 것보다 `실측 → 사건 정규화 → 공개 품질 게이트 → 관련 키워드 근거 → 기업 관계 강도`를 정직하게 보이는 것이 우선입니다.

이번 수정부터 다음 원칙을 코드 계약으로 고정합니다.

1. `unified_ranking`은 관측된 모든 항목을 제한 없이 보존한다.
2. 홈의 최대 10개는 `public_top10`만 사용하고, 미해결 항목으로 빈 칸을 채우지 않는다.
3. 관련 키워드는 X·Google 원천에서 관측된 표현만 공개한다. 운영자 후보어는 감사용으로만 보존한다.
4. 기업은 `확인된 관계`, `가치사슬 후보`, `산업 관찰`을 구분하고 산업 후보를 직접 수혜처럼 표현하지 않는다.
5. 밈트폴리오의 수익률·좋아요·사용자 구성은 목업임을 화면에서 명시한다.

### 과거 프로토타입에서 배울 점

- 트렌드 상세에서 관련 키워드와 사회 반응을 더 쉽게 탐색하게 한 점
- 기업 가치사슬을 단계별로 이동하며 이해하게 한 점
- `트렌드 발견 → 압축 해제 → 기업 탐색`이라는 서비스 은유가 명확한 점

### 되살리지 않을 점

- 한 화면에 여러 모션 체계를 동시에 넣어 핵심 판단을 늦추는 구성
- 사실 검증 전 기업·수익률을 풍부하게 채우는 방식
- SNS 게시물·좋아요를 실데이터처럼 보이게 하는 표현

## 현재 디자인 비판

### 반드시 유지할 것

- ZIP/UNZIP 은유, 보라·라임·브라운 계열, 모바일 카드 구조
- 홈 → 트렌드 상세 → 기업 관계 → 밈트폴리오 저장의 한 방향 흐름
- 현재 화면의 시각 정체성을 바꾸지 않고 데이터 상태를 보강하는 방식

### 현재 문제

1. **홈 대표 항목 계약 오류**: 전체 순위 앞 10개를 그대로 사용해 미해결 검색어가 메인에 노출됐습니다. `public_top10`으로 교체했습니다.
2. **키워드의 증거 위계 부족**: 운영자 후보어가 관련 키워드처럼 보일 수 있었습니다. 실측 표현만 칩으로 표시하도록 변경했습니다.
3. **기업 수가 신뢰처럼 보임**: 산업 후보를 넓게 만들면 항목 수는 늘지만 직접 관계가 늘어난 것은 아닙니다. 관계 단계와 팀 검수 상태를 계속 노출해야 합니다.
4. **목업 경계 부족**: 밈트폴리오 화면의 수익률·좋아요가 실측처럼 보일 수 있어 화면 내 고정 라벨을 추가했습니다.
5. **작은 보조 텍스트**: 9~11px 정보가 많아 실제 모바일에서 접근성이 약합니다. 발표 전 실기기에서 12px 이상과 명도 대비를 검증해야 합니다.
6. **데스크톱 정보밀도**: 모바일 프레임만 중앙에 놓여 큰 화면의 여백이 큽니다. S# 내부 모바일 서비스라는 발표 맥락에서는 허용되지만 일반 웹 제품으로 설명하면 미완성처럼 보입니다.
